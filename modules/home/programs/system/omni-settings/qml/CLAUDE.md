# Omni Settings: QML front end

<!-- Claude Code loads this file when it reads a file in this folder. -->

The front end is Quickshell QML in `qml/`; `omni-settings` is `qs -p $share/qml/shell.qml`, the window. The backend path and editor come from `Config.qml`, which `default.nix` writes from `qml/Config.qml.in` along with a `qmldir`, so the same files load in DMS's process: `plugin/` is the DMS plugin (`OmniPanel.qml`, a `DSlideout` with IPC target `omniSettings`), importing the built `qml/` by its store path. The panel stays open until Mod+S or its close button hides it; dragging its left edge narrows it (480 px up to the 618 px default, `defaultWidth` in `OmniPanel.qml`), and the width is kept in DMS's plugin state (`savePluginState`, `~/.local/state/DankMaterialShell/plugins/`). `OmniView.qml` holds the shell, navigation, pending changes, `ask()` (`ConfirmDialog.qml`), `sheet` and `startJob()`; generated pages are `SettingsPage.qml`/`SettingRow.qml`, and custom pages register in its `custom` map. Data comes from `src/api.py` (`omni-settings-backend <cmd> '<json>'`, one process per call), through `Backend.call`, which a long-lived `omni-settings-backend --serve` answers by forking a child per call (`api.serve`; it stops after 5 idle minutes, and calls while it's down run as their own process), or `Backend.stream` for progress lines on stderr; jobs go to the `omni-settings-jobs` service (`src/jobs.py`, `Jobs.qml`). A new custom page is a QML page in the `custom` map, `api.py` commands for its data, and its logic in a `src/*state.py` module when it's more than a few lines. Extras on a generated page (Running Now, Open Right Now, the boot versions on Boot) are components `SettingsPage.qml` loads by page or group title. When `omni-settings` is in the machine's `mullvad.splitTunnel`, `bin/omni-settings-backend` runs the real one in `libexec/` through `mullvad-exclude`, since the panel's backend calls come from DMS's process, which the split tunnel's PATH wrapper never sees.

Above the tabs and across the full width (over the rail too), `StatusHeader.qml` has two cards side by side with the NixOS logo between them (nixos-icons' 128 px PNG, installed beside the QML by `default.nix`; hidden when the cards stack under 420 px): the hostname and the user as primary pills (tapping the user opens Users), then the running version (api.py's `status`, again after each job) and a pill saying "Up to date" or how many changes wait (tapping opens Review, `startReview()`, or with none the update check). Under them a card of pills: WM, kernel and free disk in primary, release in `Theme.info` (DMS's blue), and git as its icon (the branch in its tip) followed by the collapsed Git page's yellow badges for what's waiting (`pageAlerts("git")`, from `gitCounts`). Every pill opens what it describes (a `Tag`'s `act`): the hostname the System page, WM and kernel their rows there, release the NixOS manual's release notes, disk, the version and "Up to date" their Maintenance sections, git the Git page. A jump inside a page goes through `focusOn(tab, page, key)` in `OmniView.qml`, which opens the page and then emits `focusRequested(key)`; a `SettingRow` whose setting key matches scrolls into view (`scrollToItem`) and flashes, and `OverviewPage.qml` answers its `overview:*` keys. Rebuild (`rebuildBtn` in `OmniView.qml`, admins) sits right of the tabs, over the page rail; with changes waiting it carries their count and opens Review instead (`rebuild()` and `canStart()` live in `OmniView.qml`). Then CPU and RAM, each a value and a line of its last 5 minutes (`LineGraph.qml`, from `usage` every 2 s while shown, so the history fills only while the panel is open), in primary, then yellow from 50% and red over 80% (`Theme.loadColor`), opening Resources when `status` finds it on PATH; the run page keeps the graphs alone (`barOnly`). The tabs are icons, the current one a tinted pill with its name; they spread across the bar when they fit and otherwise scroll sideways (wheel or drag) with an arrow at each edge that shows only while there's more that way, and a tab whose pages have something waiting gets a yellow dot (`tabAlerts`: Git counts or cached updates on Maintenance, firmware on Hardware). The rail's later groups start with a line, and the page names shown on hovering it carry each group's name above it (`railGap`). Titles carry no line under them: a description shows on hovering the title's text (`TitleTip.qml`, a child of that `Text`), a caution behind a yellow triangle `Hint`, both through the tooltip (`Tip.qml`, `rich` for marked-up text); `../CLAUDE.md`'s "Keep the interface clean" has the rules.

Each tab is one scroll of its pages (`tabPages` and `PageSection` in `OmniView.qml`): a divider names each rail group once (the untitled first group takes the tab's name), and each page sits in a card whose header collapses it (cards alternate a shade of lightness; the header's icon fills with primary while open, hovering its title shows the description and, collapsed, `pageSummary`, and a collapsed header shows what waits as yellow icon and count badges, each with a tip (`pageAlerts`: Git, Maintenance's Pinned Versions, Firmware); a section holding one page of its own name, like Default Packages, drops its divider for the page's header, `soleNamed`); a page's settings sit in one card per group (`SettingGroup.qml`, also used by the custom pages that hold settings), rows split by rules, and `schema.CHIPS` groups show their switches as chips (`ToggleChip.qml`). Other shared parts: `Tile.qml` for a page's key numbers (the top of Maintenance), `ActionRow.qml` for a row that runs one thing, and `OutlineButton.qml`, outlined (red for a delete) or `filled` for a card's main action, as in the Flatpaks page's button row; pages and group cards start collapsed, and the ones opened are kept in `~/.local/state/omni-settings/ui.json` (api.py's `saveUi`, sent back by `load` as `ui`). The Apps section is one Default Packages page, each category a card (api.py's `app_card`). Tooltips go through the `Tip` singleton, drawn by `OmniView.qml` at the cursor: set `tip` on an `IconButton` or use a `Hint`. Dropdowns end in a `Chevron`; `ListRow`s, tiles and action rows are dark inset cards (`Qt.alpha(Theme.bg, 0.55)`, edged in `Theme.rule`), setting rows have no fill of their own, and neutral rules and card edges take `Theme.rule`. An open page card is edged in primary, and the one under the cursor gets a firmer primary ring. The rail highlights the page at the top of the view and scrolls to the one clicked, leaving it open or shut as it was (`go`'s `keepShut`; search and links open it), its top button closes every page in the tab while any is open and otherwise opens them all (`anyOpen`, `setAllOpen`), and the section being read stays put while sections above it load (`anchorPage`). A tab fades in once every page in it is `ready` (a page that fetches data declares it), or after 700 ms. Search is pinned above the Packages scroll with its results in a dropdown, and the All user packages page shows only while there's no category.

Page-by-page behaviour and the backend modules behind each page are in `src/CLAUDE.md`.

## Gotchas

- QML reads a property named `on` plus a capital (`onPrimary`, `onLine`) as a signal handler, so it comes out undefined: the colours are `Theme.ink*`, `Backend.stream`'s callback is `each`.
- Whatever a dropdown opens goes in a `Reveal` (`Reveal.qml`) with `gap` set to the parent layout's spacing, so it slides instead of popping in; Loaders and Repeaters inside gate on its `shown`, not the open flag, so they stay until it has closed.
- Tap handlers take `gesturePolicy: TapHandler.ReleaseWithinBounds`; with the default, a click that closes a dialog also reaches the row under it.
- Inside an inline component, `view: view` binds the property to itself, which is why `OmniView`'s id is `omni`. Its JS has no `Array.flatMap`.
- JSON sent back from QML loses `.0` on whole numbers and can come back with its keys sorted, so files are written from data the backend read itself (`windowrulestate.edited`, the window rules undo). A `Repeater` delegate's `modelData` is a copy: edits go through the source list by index (`RuleEditor.qml`).
- Don't name a property after one `Item` already has (`data`, `state`): the page fails to load. Nor after one a handler has (`target`): inside a `TapHandler` the name finds the handler's own, silently.
- A `Loader` in a layout takes `Layout.preferredHeight: item ? item.implicitHeight : 0`, or the next page it loads keeps the last one's height.
- A `Loader` whose item wraps text (a `Text` sized by width) gets only `width` from its parent, inside an `Item` taking the item's `implicitHeight`; sizing it from a layout loops (`DocPage.qml`).
- Matugen has no success or warning colour, and its `tertiary` needn't be yellow: `Theme.success` and `Theme.caution` are DMS's terminal green and yellow (`dank16` color2 and color3). Status colours go through a `tone` on `ListRow`, `Badge` and `Chip`.
