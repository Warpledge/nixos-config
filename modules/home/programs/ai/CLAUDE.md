# Claude Code tooling

<!-- Claude Code loads this file when it reads a file in this folder. -->

Skills and subagents are registered in `claude.nix` under `programs.claude-code.{skills,agents}`, beside the pinned plugins and LSP servers. `agent-skills.nix` links the skills into `~/.agents/skills/` for Zed's agent and opencode, which is told to skip `~/.claude/skills/` so it doesn't list them twice. The subagents run without CLAUDE.md (`omitClaudeMd`), at medium effort except `build-triager`, which runs on Sonnet, so each one's file holds everything it needs. opencode keeps the GitHub MCP off (`opencode.nix`): it loads every tool schema up front, while Claude Code defers them.

Only `.claude/settings.json` is tracked (public); the rest of `.claude/` is gitignored, including `settings.local.json`, where "always allow" approvals land and can capture a secret. **Maintenance check:** before committing a `settings.json` change, and in any CLAUDE.md audit, read both files for tokens, keys, credentialed URLs or private paths; nothing secret goes in `settings.json`, and stale or sensitive local approvals get pruned. Bash allow rules stay read-only, since in auto mode a matching allow rule skips the safety classifier (`autoMode.classifyAllShell` is off by default). `alejandra` is the one writer (the edit hook runs it anyway). `deadnix --no-lambda-arg` (with or without ` .`) and `nix flake check`/`show`/`metadata` are exact rules, because a prefix rule would also let risky flags through (deadnix's `--edit`). `nix build`/`nix eval`/`nix log` stay off: `--impure --expr` reads and sends out any file, and `--option` can enable `builtins.exec`. Deny rules enforce rules 1 and 7 (rebuild, activation, boot, upgrade, rollback and screenshot commands), so an approved capture runs on the user's side with `!`. The `PostToolUse` hook, `modules/home/programs/ai/hooks/post-edit.sh`, runs `alejandra` on each edited `.nix` file and flags seven things: a new `---` line in `README.md`, a color literal outside `theme/` (rule 5), the name of any folder in `machines/` or `users/` (so a fork's own names too) or a `/mnt/` path in a `.nix` file under `modules/` or `lib/`, a new comment line over 89 columns in a `.nix` file, pyflakes and syntax errors (`ruff --select F,E9`) in an edited `.py` file, after a `settings.nix` edit under `machines/` or `users/` any setting `lib/settings.nix` rejects, and after a `users/_template/settings.nix` edit a reminder to add the toggle to `setup.sh`'s `apps` list. The hook matches `Write|Edit` only, so a file changed through Bash (`sed`, a heredoc) skips the formatting and the checks; the `PreToolUse` hook, `hooks/pre-bash.sh`, denies a Bash command that writes a tracked file in place (`sed -i`, `perl -i`, `>`, `>>`, `tee`) and an `rm` that uses a variable or is chained (rule 11).
