# Claude Code tooling

<!-- Claude Code loads this file when it reads a file in this folder. -->

Skills and subagents are registered in `claude.nix` from the names in the user's `claude.skills` and `claude.agents` (camelCase there, kebab-case on disk: `addApp` is `skills/add-app/`), so a new skill or subagent also needs its line in `users/_template/settings.nix` (visibility and model), `schema.py`'s Skills page and `descriptions.json`. A `claude.skillModels`/`agentModels` value rewrites the file's frontmatter `model:` at build time. Plugins (`claude.plugins.*`) and MCP servers (`claude.mcp.*`, which opencode's copies follow too) are store-managed; Claude Desktop's Code tab loads them from `~/.claude/` like the CLI, and Chat gets none. Claude Code mods (hooks modules, the `plugin-authoring` skill) are fetched pinned (Skins, File Tree, Savvy Progress, and Blast Radius and Replay Theater from one `claude-code-playground` fetch), each linked whole into `~/.claude/skills/` with `home.file` behind `claude.mods.<name>`; `mods/` holds patches (Skins': the `matugen` skin read from `~/.config/claude-skins/matugen.json`, rendered by `theme/matugen/claude-skins.json`, and no update check) and the repo's own `usage-band` mod (`programs.claude-code.plugins` links file by file, and Claude Code refuses a hooks module that resolves outside the plugin folder).

`mods/usage-band/` replaces Ribbon, whose drawings and layout it keeps (MIT, `LICENSE`), and draws in the terminal and the desktop app's Code tab: 5-hour and 7-day percent used from `$.session.usage()`, each bar with a tick at how far through its window you are (fill past the tick is ahead of an even pace), context used, and on the row below the prompt cache's warm or cold state. Its colours come from `~/.config/claude-usage-band/matugen.json` (`theme/matugen/claude-usage-band.json`), re-read every 30 seconds; until DMS's matugen has rendered it, the band uses theme keys and drops the art, so no colour lives in the mod. Its per-model cache prices sit in `hooks/cache-art.ts`. It shows no peak hours: Anthropic removed Claude Code's peak-hour limit cut for Pro and Max on 2026-05-06 (anthropic.com/news/higher-limits-spacex). `claude.mods.rebuildPrompt` adds buttons reading the same facts as the opencode badge (`hooks/repo-state.ts`): Rebuild runs `dms ipc call omniSettings rebuild`, which only opens the Rebuild dialog, and Restart DMS shows, with one toast per build, when `dms.service` runs a store path other than the one on PATH. `claude.nix` fills `__FLAKE_PATH__` and `__REBUILD_PROMPT__` in the store copy, so to check the mod, fill them in a copy first. The engine refuses `$` passed into a function from another file, though `claude plugin test` can let it through, so helpers in `hooks/` take plain values or callbacks. Everything else (built-in plugins, `skillOverrides`, blocked claude.ai connectors in `deniedMcpServers`, model, effort, output style, the `claude.statusLine` script) goes into `declared` in `claude.nix`, merged into `~/.claude/settings.json` with `lib/mutable-merge.jq` like Zed's settings, so changes made in Claude Code stay until the same setting changes in the repo; the Claude Code switch's reset in Omni Settings puts `~/.claude/declarative-settings.json` back. Check a mod with `claude plugin validate` and `claude plugin test` on its folder. `agent-skills.nix` links the skills into `~/.agents/skills/` for Zed's agent and opencode, which is told to skip `~/.claude/skills/` so it doesn't list them twice. The subagents run without CLAUDE.md (`omitClaudeMd`), so each one's file holds everything it needs: the reviewers on Sonnet at medium effort, `build-triager` on Haiku. The `commit` skill runs forked on Sonnet and `freetube-sync` and `apparmor-check` forked on Haiku (`context: fork`): they can't see the chat, so the caller passes what they need as the argument, and they return questions instead of asking. opencode keeps the GitHub MCP off (`opencode.nix`): it loads every tool schema up front, while Claude Code defers them, and it loads its own copies of the subagents from `opencode-agents/`, which override the ones in `~/.claude/agents`; edit both when a prompt changes. Pi (`pi.nix`) leaves it off too; it gets the other servers in `~/.pi/agent/mcp.json`, with a keyed server wrapped in a script that reads its key file at launch, and that file and `settings.json` (its default model and the `dank` matugen theme) are merged with `mutable-merge.jq`, since `pi mcp add` and `/settings` write them. `llama-swap.nix` writes its `models.json`, the same models as opencode's.

`opencode-usage-bar/` is a local OpenCode V2 plugin (server, TUI and desktop parts over RPC) that shows the Go plan's Console spend for the last 5 hours and the UTC week: bars in the terminal's prompt and home footers and a coloured bar in the desktop app's `window.bottom` strip, plus DeepSeek's peak hours. Its server part reads the `opencode` OAuth credential that `/connect` stored, so a footer or bar stuck on `usage ?` means that session expired; signing in again fixes it. Percentages are each model's Console cost divided by that model's Go monthly limit, the same figure the Console's Go page shows; `limits.ts` holds the Go, Go Plus and Go Teams tables, selected on the plugin's settings page. The Console exposes no plan-block endpoint to a member, so the 5-hour figure is spend over the last 5 hours, not the plan's own block. The desktop bar's PEAK/OFF-PEAK note shows only with DeepSeek usage in the last 5 hours, since the desktop plugin API has no current model to read. The same server part watches `machine.flakePath`, whatever project the session is in, and `/nix/var/nix/profiles/system`: after a turn it emits an RPC event, and the desktop part shows a green `session.header` badge with Omni Settings' sync glyph while commits or files are newer than the running build. Clicking the badge or the titlebar item runs `dms ipc call omniSettings rebuild`, which opens the panel on its own Rebuild dialog (`OmniPanel.qml`, `rebuildWanted` in `OmniView.qml`), so the mode choice and `canStart()` stay in one place. A "DMS restart needed" toast with a Restart button appears once per stale build when `dms.service` runs a store path other than the one on PATH. The desktop part is a hand-written `gui-experimental.cjs`: the GUI bundle otherwise needs a Vite build, and the bar is DOM built in that file, coloured with the app's `--color-v2-*` variables. Each part is a switch under Omni Settings' AI, OpenCode: `opencode.nix` fills `__TUI__`, `__DESKTOP_BAR__`, `__REBUILD_BADGE__` and `__FLAKE_PATH__` in the plugin's store copy, which the TUI, the bar, the badge and the server part read.

`claudeDesktop.matugen` patches Claude Desktop at build time: `claude-desktop.nix` adds `claude-desktop/matugen-theme.js` to `app.asar` and loads it right after the `"use strict";` that starts `.vite/build/index.pre.js`, failing the build if that line changes. The script inserts `~/.config/claude-desktop/matugen.css` into every window and re-inserts it when matugen rewrites it. The template (`claude-desktop/matugen.css.matugen`) only overrides the app's colour variables: the chat's HSL triples (`--bg-*`, `--text-*`, `--border-*`, `--accent-*`, `--brand-*`, status) and the Code tab's `--cds-*` tokens. When an update leaves part of the app stock, extract the new `resources/app.asar` and `ion-dist` CSS and look for renamed variables before touching selectors.

Only `.claude/settings.json` is tracked (public); the rest of `.claude/` is gitignored, including `settings.local.json`, where "always allow" approvals land and can capture a secret. **Maintenance check:** before committing a `settings.json` change, and in any CLAUDE.md audit, read both files for tokens, keys, credentialed URLs or private paths; nothing secret goes in `settings.json`, and stale or sensitive local approvals get pruned. Bash allow rules stay read-only, since in auto mode a matching allow rule skips the safety classifier (`autoMode.classifyAllShell` is off by default). `alejandra` is the one writer (the edit hook runs it anyway). `deadnix --no-lambda-arg` (with or without ` .`) and `nix flake check`/`show`/`metadata` are exact rules, because a prefix rule would also let risky flags through (deadnix's `--edit`). `nix build`/`nix eval`/`nix log` stay off: `--impure --expr` reads and sends out any file, and `--option` can enable `builtins.exec`. Deny rules enforce rule 1 (rebuild, activation, boot, upgrade and rollback commands). The `PostToolUse` hook, `modules/home/programs/ai/hooks/post-edit.sh`, runs `alejandra` on each edited `.nix` file and flags seven things: a new `---` line in `README.md`, a color literal outside `theme/` (rule 5), the name of any folder in `machines/` or `users/` (so a fork's own names too) or a `/mnt/` path in a `.nix` file under `modules/` or `lib/`, a new comment line over 89 columns in a `.nix` file, pyflakes and syntax errors (`ruff --select F,E9`) in an edited `.py` file, after a `settings.nix` edit under `machines/` or `users/` any setting `lib/settings.nix` rejects, and after a `users/_template/settings.nix` edit a reminder to add the toggle to `setup.sh`'s `apps` list. The hook matches `Write|Edit` only, so a file changed through Bash (`sed`, a heredoc) skips the formatting and the checks; the `PreToolUse` hook, `hooks/pre-bash.sh`, denies a Bash command that writes a tracked file in place (`sed -i`, `perl -i`, `>`, `>>`, `tee`) and an `rm` that uses a variable or is chained (rule 9). The `SessionStart` hook, `hooks/session-start.sh`, prints one line naming any waiting note in `.claude/handoffs/` (the `handoff` skill, used instead of `/compact`) on startup and after `/clear`.
